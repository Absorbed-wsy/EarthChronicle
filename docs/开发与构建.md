# 开发与构建

## 当前架构与 EXE

Windows 外壳使用 .NET Framework 4.8 / WinForms，WebView2 显示本地网页。原生进程管理随包 Node.js 后端，SQLite 统一保存内置资料、个人记录和设置；Cesium 负责地球与平面地图。网页阅读使用可选的独立只读监听端口。

当前已经可以编译出 `EarthChronicle.exe`。它是桌面程序入口，仍依赖同目录的 Node、WebView2 SDK DLL、网页资源及资料文件，不能只复制一个 EXE 就运行完整软件。以后可以制作安装 EXE 或带完整目录的便携包，无需为此重写界面。真正单文件免解压运行不作为当前目标，数据库也应保持可独立备份与迁移。

## 从源码构建

环境：Windows 10/11 x64、.NET Framework 4.8、WebView2 Evergreen Runtime，以及 Windows 提供的 PowerShell、curl、tar。运行组件无需管理员权限；首次准备依赖需要网络。

在项目根目录运行：

```powershell
powershell -NoProfile -File desktop/prepare.ps1
./runtime/node.exe --test tests/*.test.mjs
powershell -NoProfile -File desktop/test.ps1
powershell -NoProfile -File desktop/build.ps1
```

`prepare.ps1` 从 Node.js 官方分发站、npm 的 Cesium 包及 Microsoft NuGet 包下载 Node 24.19.0、Cesium 1.145.0、WebView2 SDK 1.0.4191.47，先核对固定摘要再复制运行文件。原生编译器读取系统路径，无需额外引入 Electron。

准备脚本不安装 WebView2 系统运行时；缺少它时，软件会提示安装。生产分发需依照 [微软的 WebView2 部署说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution) 检测或引导安装。

网络受限时，可在已联网的开发机器保留 `.build-cache` 中三个下载文件，在另一台机器通过 `desktop/prepare.ps1 -CachePath <缓存目录>` 复用。脚本仍校验每个文件的摘要。缓存不包含个人数据库。

## 目录与测试

- `desktop/`：原生外壳、构建、依赖准备、原生测试和更新工具。
- `public/`：自有前端及作为初始化资料的 `data/`；Cesium 构建产物放在忽略目录 `public/vendor/cesium/`。
- `server.mjs`、`database.mjs`：权限边界、内容服务器、SQLite 与迁移。
- `tests/`：日期/筛选、真实数据库与服务、前端异步状态、原生请求及更新工具回归。
- 运行期 `data/`：数据库、日志、状态及 WebView2 用户目录，全部不入库。
- `backups/`：更新前本机备份，不入库。

JavaScript 测试使用临时数据库和本机回环端口；原生测试不会打开软件窗口。真实地球渲染与托盘行为仍需要桌面操作验收。GitHub Actions 会在 Windows 上准备依赖、运行测试并编译 EXE。

已有资料必须在更新前使用 SQLite 一致性备份，不能把开发数据库复制给用户。`ApplyUpdate.ps1` 用于带 `files/` 和 `manifest.json` 的更新包，不是启动入口。开发构建不会自动生成更新包或发布 GitHub Release。
