# 下一阶段设计目标

本文是后续开发建议，不表示下述功能已实现。建议 v0.4 先完善时间、地点和事件的数据基础，再独立交付安装与升级能力。沿用当前界面、皮肤、地图操作及分类设置，不重新设计整套交互。

## P0：统一时间表达

历史事件支持公元前、公元纪年，界面不出现公元 0 年；数据库采用可计算的统一时间值，并保留原始纪年、换算依据。支持单年、起止范围、“约某年”和不确定范围；区分“事件持续多年”与“发生年份尚不确定”。年号作为原始记录和辅助显示，先明确支持范围，不承诺自动换算所有历法。

文明、史前与地质时间分层浏览：史前事件可记录“距今约多少年”及基准，地质仍用 Ma。时间轴随篇章选择合理尺度，不将亿年变化挤进逐年滑块。

验收：公元前 1 年向后一步到公元 1 年；跨纪元排序、筛选和持续事件重叠结果正确。约数和不确定区间始终可见，不被显示成精确年份；原始日期及依据可追溯。

## P0：建立跨年代地点与事件关系

地点具有稳定编号，名称、别名、有效年代及位置依据单独记录。现代城市、古城、遗址和山脉可以关联，但不因名称相近自动视为同一地点。位置明确标注为精确点、近似点或区域；没有可靠坐标时允许仅保留文字位置。

事件支持多个地点及角色，例如出发地、到达地、发生地；类型采用可扩展分类，保留个人记录入口。旧有单地点记录自动转换为一个“发生地”，不改变既有内容。

验收：同一地点在两个年代能显示相应名称和出处；多地点事件可从任一关联地点找到；近似位置带说明，无坐标事件仍可检索阅读。迁移前后的个人记录数量、内容与来源一致。

## P1：用篇章验证数据结构

保留明初篇章，增加一个范围受控的史前示范篇章，先核定主题、年代和资料来源。篇章决定时间范围、默认视野和可见事件，切换时同步更新列表、地图与时间轴。搜索应明确作用于当前篇章还是全部资料，避免隐藏的筛选条件造成误解。

每条内置事件保留出处、位置精度与时间精度。内置资料仍只读；个人事件可归入篇章，也可独立保存。地质切片与文明事件分别管理，不允许个人记录改写固定模型。

明确区分备份恢复与数据库合并：恢复重建某个快照，合并保留记录的删除状态，并制定同一事件两边均有修改时的冲突规则。避免导入旧资料时无意恢复已删除记录。

验收：两个篇章可往返切换，选中事件始终属于当前结果；跨篇章查询能返回所属篇章；网页端只读限制继续有效。数据库升级、备份恢复和旧版本拒绝提示有明确行为，不丢失个人记录；重复合并不产生重复事件，已删除记录不会被旧数据库意外恢复。

## P2：单独完成安装与升级

数据基础稳定后，再制作 Windows 安装包：分离程序文件与用户数据库，提供桌面入口、运行环境检查、更新前备份和失败恢复。升级保留个人资料及设置；卸载是否删除资料必须明确选择。此阶段不与 v0.4 数据迁移同时扩大范围。

验收：在干净 Windows 环境完成安装、首次启动、旧版升级和卸载；验证数据库保留及备份恢复，并检查本地窗口与网页阅读权限。

## 暂缓事项

暂缓全球通史批量覆盖、连续板块运动、精确古海岸线与古地形、历史疆域动画、多人协作、公网账号和游戏机制。先用少量可核对资料证明时间与地点模型可用，再逐章扩充；地质模型与史料存在的不确定性持续保留，不以视觉效果代替证据。
